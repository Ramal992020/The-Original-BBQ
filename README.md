# 🔥 The Original BBQ — تطبيق طلبات كامل (عميل + إدارة + صلاحيات + إشعارات + واتساب + دفع أونلاين)

تطبيق كامل بسيرفر حقيقي: **تسجيل دخول، أدوار (Customer / Supervisor / Admin)، طلبات، لوحة إدارة،
إشعارات فورية، إدارة منيو، رفع/توليد صور، إشعارات واتساب للعميل، ودفع أونلاين (Stripe / Paymob / محاكاة)**
— كله من غير أي مكتبات خارجية للتشغيل.

---

> **📦 لرفعه على GitHub ثم Vercel:** كل حاجة جاهزة — شوف ملف **[DEPLOY.md](DEPLOY.md)** (خطوة بخطوة بالتفاصيل + جدول حل المشاكل، ٥ دقايق).
> المشروع بيدعم **الوضعين**: سيرفر عادي (ملفات JSON + بث لحظي) و Vercel (سيرفرلس + Upstash Redis) — بيختار لوحده.

## ١) التشغيل في ٣٠ ثانية

```bash
cd original-bbq-app
npm start          # أو: node server/index.js
```
بعدين افتح: **http://localhost:3000**

### حسابات الدخول الجاهزة
| الدور | الإيميل | كلمة السر | يقدر يعمل إيه |
|---|---|---|---|
| **Admin** (صاحب المطعم) | `admin@bbq.app` | `admin123` | كل حاجة: منيو، صور، مستخدمين، إعدادات + كل صلاحيات المشرف |
| **Supervisor** (الكاشير) | `supervisor@bbq.app` | `super123` | يشوف كل الطلبات، يغيّر الحالة، بيانات العملاء، إشعارات |
| **Customer** | `demo@bbq.app` | `demo123` | يطلب ويتابع طلباته فقط (مفيش أي وصول للإدارة) |

> ⚠️ **غيّر كلمات السر دي قبل أي استخدام حقيقي**، وشيل الدخول السريع: شغّل السيرفر بـ `DEMO_LOGIN=0 npm start`.

## ٢) الوظائف اللي اتطلبت — واحدة واحدة

### 🖼️ توليد صور الطعام للأصناف المستوردة تلقائيًا
- الـ**٥٠ صنف** المستوردين من تطبيقك القديم كلهم عندهم صور **مولّدة خصيصًا** (مش صور مكررة).
- أي **صنف جديد** الأدمن يضيفه → السيرفر يولّدله صورة **تلقائيًا** حسب اسمه وتصنيفه.
- في لوحة الإدارة → المنيو: زر **«ولّد صور للأصناف بدون صورة»** وزر **«ولّد صور لكل الأصناف المستوردة»**.
- **تغيير الصورة يدويًا** بأي طريقة من التلاتة:
  1. **رفع صورة** من جهازك (بتتضغط تلقائيًا وتتحفظ في `uploads/`).
  2. **اختيار من مكتبة صور** جاهزة (١٨ صورة: ٩ مولّدة بالذكاء الاصطناعي + ٩ صور تطبيقك الأصلية).
  3. **توليد صورة جديدة بالذكاء الاصطناعي** بضغطة لصنف واحد.

**مزوّد الصور:** افتراضيًا بيشتغل من المكتبة المدمجة (بدون أي مفتاح، فشغال من أول لحظة).
لو عايز توليد صور جديدة فعلية لكل صنف، حط مفتاح في البيئة قبل التشغيل:
```bash
GEMINI_API_KEY=xxxx npm start        # أو OPENAI_API_KEY=xxxx npm start
```
وبعدها زر «ولّد صور» هيولّد صور جديدة حقيقية لكل صنف حسب وصفه.

### 👤 المستخدمون والأدوار
- جدول المستخدمين: `id · الاسم · الإيميل · role · active`.
- **أي حساب جديد بيتسجل = Customer تلقائيًا** (مش ممكن حد يختار لنفسه دور أعلى).
- الأدمن من صفحة **المستخدمون** بيغيّر أي حد لـ Supervisor، ويفعّل/يعطّل الحسابات.
- **الحساب المعطّل مايقدرش يسجل دخول، وكل جلساته بتتقفل فورًا** (متحقق منه في الاختبارات).

### 🔐 الصلاحيات — على السيرفر مش على الشاشة
| العملية | Customer | Supervisor | Admin |
|---|:--:|:--:|:--:|
| يشوف طلباته هو بس | ✅ | ✅ | ✅ |
| يشوف طلبات الكل | ❌ | ✅ | ✅ |
| يغيّر حالة الطلب | ❌ | ✅ | ✅ |
| بيانات العملاء | ❌ | ✅ | ✅ |
| إدارة المنيو والصور | ❌ | ❌ | ✅ |
| إدارة المستخدمين والأدوار | ❌ | ❌ | ✅ |
| الإعدادات | ❌ | ❌ | ✅ |

كل طلب API بيتفحص صلاحيته جوه السيرفر: **عميل بيفتح `#/admin` بالرابط المباشر = 403 من السيرفر**،
وتفاصيل طلب شخص تاني = 403. (الاختبارات التلقائية تغطّي ده كله — شغّل `npm test`).

### 🧾 الطلبات و Order Items
- كل طلب: **رقم الطلب، user_id، اسم العميل، الهاتف، العنوان، الملاحظات، طريقة الدفع، الإجمالي، الحالة، التاريخ والوقت**.
- **Order Items**: الطلب، الصنف، الكمية، السعر، الإجمالي (لكل سطر) + الإضافات والملاحظات.
- كل طلب **مربوط بالمستخدم المسجل** — يقفل ويفتح من أي جهاز ويشوف طلباته.
- الأسعار والإجماليات بتتحسب **على السيرفر** (متحقق: محاولة تغيير السعر من المتصفح بتترفض).

### 🔄 الحالات (Timeline وليس GPS)
`طلب جديد` ← `تم استلام الطلب` ← `جاري التجهيز` ← `خرج للتوصيل` ← `تم التوصيل` · + `ملغي`
- العميل يشوفها **Timeline واضح** بالتوقيت وسجل كامل لكل تغيير.
- المشرف/الأدمن يغيّر الحالة، و**العميل بيشوف التحديث فورًا** في «طلباتي»
  (بث مباشر SSE — من غير أي إعادة نشر للتطبيق، ولو الاتصال وقع بيرجع تلقائيًا).

### 🧑‍🍳 لوحة الإدارة
- تظهر **فقط** لو المستخدم Admin أو Supervisor (في الواجهة والسيرفر).
- ملخص اليوم: **طلبات جديدة / تم استلامها / جاري التجهيز / خرجت للتوصيل / تم التوصيل / ملغية / إجمالي مبيعات اليوم**.
- صفحة إدارة طلبات فيها **فلاتر بحسب الحالة مع عدد الطلبات في كل حالة** + بحث (رقم الطلب، الاسم، الهاتف، العنوان، الإيميل)
  + فلتر «النهارده بس».
- كل طلب: رقمه، العميل، الهاتف (اتصال وواتساب بضغطة)، العنوان، المنتجات، الإجمالي، الوقت والحالة + تفاصيل كاملة في لوحة جانبية.

### 🔔 الإشعارات
- عند وصول طلب جديد → إشعار **للأدمن والمشرفين فقط** (العميل لا يستقبل إشعارات الإدارة).
- الإشعار فيه: **طلب جديد، رقم الطلب، اسم العميل، الإجمالي** — والضغط عليه **بيفتح تفاصيل الطلب**.
- إشعار إضافي عند **نجاح الدفع** («تم دفع طلب 💳»).
- بتوصل **لحظيًا** (SSE) مع توست، وفي جرس إشعارات بعدّاد غير المقروء.

### 💬 إشعارات واتساب للعميل
- عند كل تغيير في حالة الطلب → رسالة واتساب للعميل فيها حالة الطلب ورقمها.
- رسائل تلقائية أخرى: **تأكيد استلام الطلب** (وفيها رابط تتبع الطلب)، **تأكيد الدفع**، و**رابط الدفع**.
- **إشعار للمطعم**: اول ما طلب جديد يوصل، رسالة على أرقام المطعم (لو مفعّل).
- **٧ مزوّدين** تشتغل بيهم من غير أي كود — تبدّل من اللوحة (تبويب 💬 واتساب):

| المزوّد | إيه اللي محتاجه | مناسب لمين |
|---|---|---|
| 🖨️ **console** (افتراضي) | مفيش حاجة | تجربة فورية — الرسالة بتتطبع في نافذة السيرفر |
| 🔗 **link** | مفيش حاجة | من غير API: بضغطة واحدة بيفتح واتساب بالرسالة جاهزة |
| **Meta** (WhatsApp Cloud API) | Access Token + Phone Number ID | الرسمي من Meta — الأفضل للإنتاج (في قوالب معتمدة) |
| **Twilio** | Account SID + Auth Token + رقم | أسهل في البداية (فيه Sandbox للتجربة) |
| **Green API** | Instance ID + Token | شغال بأي رقم واتساب عادي بمسح QR |
| **UltraMsg** | Instance ID + Token | زي Green API — شهير في مصر |
| **CallMeBot** | API Key | مجاني تمامًا (اتجاه واحد) للتنبيهات البسيطة |

**كمان في اللوحة:** تفعيل/إيقاف، اختيار على أي الحالات تتبعت، **تعديل نص كل رسالة** بالعربي، أرقام المطعم،
وسجل كامل لكل رسالة (اتبعتت / فشلت / رابط) مع زر **إعادة إرسال** وزر **فتح المحادثة** جاهز.

**المتغيرات المتاحة في أي رسالة:** `{name}` `{order}` `{total}` `{phone}` `{eta}` `{address}` `{link}` `{paylink}`

> 🔐 احترام الخصوصية: العميل بيوافق بنفسه (علامة في صفحة الحساب وفي الشيك أوت)، ولو وقّفها **مش هيوصله أي رسالة**
> والسبب بيتسجل في سجل الواتساب عندك.

### 💳 الدفع أونلاين
- صفحة الدفع عندك ٣ طرق: **نقدًا** · **بطاقة عند التوصيل** · **دفع أونلاين** (تتفعّل/تتقفل من اللوحة).
- ٣ مزوّدات (تبويب 💳 الدفع في اللوحة):

| المزوّد | إيه اللي محتاجه | ملاحظة |
|---|---|---|
| 🧪 **محاكاة (demo)** — الافتراضي | مفيش حاجة | صفحة دفع تجريبية جاهزة (`/pay.html`) — **تجرّب الدورة كاملة من أول لحظة** |
| **Stripe** | Secret Key + Webhook Secret | صفحة دفع مستضافة — مناسب لو حسابك في بلد مدعوم |
| **Paymob** (Accept) | API Key + Integration ID + Iframe ID + HMAC Secret | **الأشهر في مصر**: بطاقات + محافظ إلكترونية |

**خطوات Stripe (٥ دقايق):**
1. هات المفاتيح من dashboard.stripe.com → Developers → API keys.
2. حطهم في اللوحة → 💳 الدفع → Stripe → احفظ.
3. من Developers → Webhooks ضيف العنوان اللي ظاهرلك في الصفحة (`https://your-domain.com/api/webhooks/stripe`)
   على حدث `checkout.session.completed` — **مهم جدًا**: التوقيع هو اللي بيأكد الدفع.
4. اضغط «🔌 اختبار الاتصال» للتأكد.

**خطوات Paymob (مصر):**
1. من لوحة Paymob هات API Key، و**Integration ID** (للبطاقات/المحافظ)، و**Iframe ID**، و**HMAC Secret**
   (من Settings → Account info).
2. حطهم في اللوحة → 💳 الدفع → Paymob → احفظ.
3. في Paymob ضيف الـ**Processed Callback** على العنوان الظاهرلك (`https://your-domain.com/api/webhooks/paymob`).
4. جرّب «🔌 اختبار الاتصال».

**إزاي بيشتغل الدفع (تقنيًا):**
- العميل يختار «دفع أونلاين» → الطلب بيتسجل وحالته **بانتظار الدفع** + رابط دفع مولّد **من السيرفر بالمبلغ الصح**.
- العميل يتوجّه لصفحة الدفع (Stripe / Paymob / صفحة المحاكاة).
- التأكيد النهائي بييجي **من Webhook موقّع بتوقيع حقيقي** (HMAC) — مش معتمدين على رجوع المتصفح لوحده.
  وكمان فيه تحقق ثاني لو رجع العميل للصفحة (`/verify` بيقرا الحالة من المزوّد نفسه).
- بعد التأكيد: الطلب بيبقى **مدفوع** + **إشعار للإدارة** + **رسالة واتساب شكر للعميل** بضغطة معمارة واحدة.
- في اللوحة: **فلتر بـ«مدفوع / معلّق / فشل / مرتجع»**، تعليم الطلب كمدفوع يدويًا (للكاش/التحويل)، تسجيل مرتجع،
  وزر **«ابعت رابط الدفع»** لو العميل ماكمّلش الدفع.
- **المبالغ بتتحسب على السيرفر دايمًا** — المتصفح مش قادر يغيّر أي مبلغ، وده متحقَّق منه في الاختبارات.

### 💬 واجهة العميل
التنقل: **الرئيسية · اطلب الآن · السلة · طلباتي · حسابي** (+ تبويب **الإدارة** بيظهر تلقائيًا للمشرف/الأدمن).
- **الثيم من ألوان اللوجو الكامل**: `day` / **النهار داكن** (`#0D0A08`) افتراضيًا، و`night` / **الليل فاتح** (`#FDF9F3`) — حسب خطة الهوية، وليس حسب إعداد النظام أو الساعة. زر التبديل في الهيدر والحساب؛ الاختيار محفوظ في `bbq_theme`، مع دعم القيم القديمة `dark` / `light`. صفحة الدفع تشترك في `theme.js` والتنسيقات نفسها.
- **صفحة الطلب `#/orders`**، و`#/menu` رابط متوافق لها. سجل **«طلباتي» أصبح `#/my-orders`**؛ تفاصيل الطلب والتتبع ما زالت في `#/order/…`.
- الشعار SVG كامل بنسبة **841.9 × 595.3**، هيدر **56 × 40px**، وشاشة تحميل متحركة؛ Cairo للعناوين والأسعار وTajawal للنصوص، **محليًا بدون Google Fonts**.
- كروت أفقية بحافة نارية متناوبة وشارات مائلة، سلة عائمة متدرجة في النهار وسوداء في الليل، وخلفية بخطوط شواء خفيفة. «حار» و«متوفر للطلب» يتحكّم فيهما الأدمن من تعديل الصنف.
- **الأسعار والعملة الحالية محفوظة**؛ الأرقام عربية و`SAR` تُعرض `ر.س` و`EGP` تُعرض `ج.م`، بدون تحويل أسعار الجنيه إلى ريال بمجرد تغيير الشكل.
- تفاصيل التنفيذ والاختبارات: **[دليل الواجهة](docs/INTERFACE.md)**.
- منتجات بصور وأسماء وأسعار وتصنيفات + بحث وترتيب.
- السلة: تعديل الكميات، الحذف، الإضافات، الملاحظات، كود خصم، وحساب الإجمالي.
- قبل التأكيد: **الاسم، الهاتف، العنوان، الملاحظات، طريقة الدفع**.
- عند التأكيد: يتعمل Order + Order Items وحالته الأولى **«طلب جديد»**.

## ٤) النشر (خليها شغالة للعملاء)

التطبيق سيرفر Node — يعني محتاج استضافة تشغيل (مش استضافة ملفات ثابتة):
1. **أبسط حل:** أي VPS رخيص (Contabo/DigitalOcean) → رفع المجلد → `npm start` →
   خليها شغالة بـ `pm2 start server/index.js --name bbq` أو `systemd`.
2. **بدائل بضغطة:** Render / Railway / Fly.io — اسحب المجلد أو اربطه بـ GitHub،
   أمر التشغيل `npm start`، والبورت من متغير `PORT` (السيرفر بيقراه تلقائيًا).
3. **بعد النشر:**
   - غيّر `adminPin`… قصدي كلمات سر الحسابات الجاهزة أو اعمل حسابات جديدة وشيل القديمة.
   - شغّل بـ `DEMO_LOGIN=0` عشان تقفل الدخول السريع.
   - حط `APP_URL=https://yourdomain.com` عشان روابط استعادة كلمة السر تطلع صح.
   - حط `ADMIN_PASSWORD=...` عشان حساب الأدمن يبقى بكلمة سر من البيئة (مش `admin123`).
   - **HTTPS مهم** — أي استضافة من دول بيدّيه تلقائيًا.

## ٥) قبل ما تشغّل واتساب/الدفع فعليًا

```bash
# 1) دومين حقيقي (مهم لروابط استعادة كلمة السر وروابط الدفع ولوحة المزوّدين)
APP_URL=https://your-domain.com npm start

# 2) لو عايز توليد صور AI حقيقية لكل صنف
GEMINI_API_KEY=xxx npm start

# 3) لو عايز إيميل استعادة كلمة سر حقيقي (بدل الـconsole)
RESEND_API_KEY=xxx MAIL_FROM="BBQ <no-reply@your-domain.com>" npm start

# 4) اقفل الدخول التجريبي في الإنتاج
DEMO_LOGIN=0 npm start
```

**ترتيب مقترح للتشغيل:**
1. اضبط بيانات المطعم (تبويب ⚙️ الإعدادات).
2. شغّل الواتساب على **console** واعمل طلب تجريبي — هتشوف الرسائل بتتطبع عندك. وبعدها حوّل على المزوّد الحقيقي.
3. سيب الدفع على **محاكاة** لحد ما تخلّص تجربة الطلب كامل، وبعدها فعّل Paymob أو Stripe.

## ٦) ملاحظات أمان (اقراها)

- ✅ كلمات السر متشفرة (scrypt + salt)، الجلسات بتتقفل بعيد عن الحساب المعطّل، وفي حماية من تكرار محاولات الدخول.
- ✅ كل صلاحية بتتفحص على السيرفر، وأسعار الطلبات بتتحسب على السيرفر (مش من المتصفح).
- ✅ منع الوصول للملفات خارج `public/` (path traversal متغطي باختبار).
- ⚠️ **قاعدة البيانات ملفات JSON** — ممتازة لمطعم واحد، لكن لو بقيت فروع كتيرة أو طلبات بمئات يوميًا،
  الأحسن التحويل لـ SQLite/Postgres (بنية الكود معمولة عشان تحويل `store.js` لوحده يكفي).
- ⚠️ **الإيميلات** افتراضيًا بتتطبع في الـconsole (عشان تشتغل من غير إعدادات). لاستعادة كلمة سر حقيقية
  حط `RESEND_API_KEY` وشغّل السيرفر.
- ✅ **مفاتيح الواتساب والدفع** بتتخزن على السيرفر بس، وبتتعرض في اللوحة **مقنّعة** (آخر ٤ حروف)، ومستحيل تظهر في أي API للعميل.
- ✅ **تأكيد الدفع بتوقيع موقّع** (Stripe signature / Paymob HMAC) — أي Webhook بتوقيع غلط بيترفض ومش بيغيّر أي حالة (متحقَّق في الاختبارات).
- ✅ **صفحة الدفع التجريبية محمية بتوكن** لكل طلب — مفيش حد يقدر يعلّم طلب حد تاني كمدفوع.
- ✅ إرسال واتساب بيحترم موافقة العميل، وكل رسالة بتتسجل (مين، إمتى، ونجحت ولا لأ).
- ✅ **`ADMIN_PASSWORD`** (اختياري بس يُفضّل على الإنتاج): كلمة سر الأدمن بتيجي من متغيرات البيئة
  وبيترجّع لها الحساب مع كل إقلاع — كده مفيش `admin123` على الإنتاج، ولو نسيتها تغيّر المتغير وتعمل Redeploy.
- ⚠️ خُد **نسخة احتياطية** دوريًا: زر «نسخة احتياطية» في الإعدادات، أو انسخ مجلد `server/data`.

## ٦.٥) النشر على Vercel (سيرفرلس)

المشروع **جاهز لـ Vercel** — وفيه محرّك تخزين بيتحوّل تلقائيًا:

| | سيرفر عادي (VPS / Render) | Vercel (سيرفرلس) |
|---|---|---|
| التخزين | ملفات JSON في `server/data` | **Upstash Redis** (REST — بدون أي مكتبات) |
| البث اللحظي | ✅ SSE (لحظي) | 🔄 تحديث دوري كل ٢٠ ثانية (الواجهة بتتبدّل تلقائيًا) |
| رفع الصور | على القرص | مخزّنة في قاعدة البيانات وبتتقدم من `/api/img/:id` |
| الباقي (طلبات، صلاحيات، دفع، واتساب، إشعارات) | ✅ | ✅ |

**الخطوات بالتفصيل في [DEPLOY.md](DEPLOY.md)** — الملخص:
1. ارفع الريبو على GitHub.
2. اعمل قاعدة **Upstash Redis** مجانية وخُد `REST URL` + `TOKEN`.
3. على [vercel.com/new](https://vercel.com/new) اعمل Import للريبو وضيف متغيرات البيئة:
   `UPSTASH_REDIS_REST_URL` · `UPSTASH_REDIS_REST_TOKEN` · `APP_URL` · `ADMIN_PASSWORD` · `DEMO_LOGIN=0`
4. **Redeploy** (المتغيرات مش بتتطبّق على deploy قديم).
5. اتأكد: `/api/health` → `"storage":"redis"` و`"persistent":true`، أو تبويب **🛠️ النظام** في لوحة الإدارة.

> 📌 **دليل مصغّر بالصور للمتغيرات الأربعة:** [`docs/VERCEL-UPSTASH.md`](docs/VERCEL-UPSTASH.md)
> (from إنشاء قاعدة Upstash لحد Redeploy والتأكد، وحلّ كل غلطة شايعة).

**عايز تجرّبه محليًا في وضع Vercel؟**
```bash
npm run fake-redis                              # تيرمنال ١ (محاكي Upstash)
STORAGE=redis UPSTASH_REDIS_REST_URL=http://127.0.0.1:4599 \
  UPSTASH_REDIS_REST_TOKEN=x VERCEL=1 npm start # تيرمنال ٢
npm run test:vercel                             # ٢١ اختبار آلي لوضع Vercel
```

> ⚖️ **أي واحد تختار؟** لو عايز أسهل إعداد → Vercel + Upstash. لو عايز اللحظية القصوى (الطلب يظهر للكاشير
> في نفس اللحظة) → **Render** من نفس الريبو بنفس الكود وبدون أي إعداد إضافي (فيه قسم كامل في DEPLOY.md).
